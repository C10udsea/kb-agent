# 嵌入式通信接口

## 嵌入式通信的分类

嵌入式系统中的通信接口分为芯片内部或板级通信、设备间总线通信和网络通信。板级通信常见 UART、SPI、I2C；工业现场常用 RS485、CAN；设备联网常用以太网、Wi-Fi、MQTT 等协议。选择接口时要综合考虑速率、距离、节点数量、线缆成本、实时性和抗干扰能力。

## UART 串口

UART 是异步串行接口，通常只需要发送、接收和地三根线。数据以起始位、数据位、校验位和停止位组成的帧格式传输，收发双方需约定相同波特率。

UART 没有独立时钟线，接收端在起始位下降沿后按波特率进行过采样恢复数据。优点是简单、通用、适合点对点低速通信；缺点是速率较低、距离有限，多机通信需要额外协议。RS232 是传统串口电平标准，逻辑电平与 TTL 不同，需要通过电平转换芯片连接。

## SPI 总线

SPI 是同步串行外设接口，采用主机-从机结构，使用 SCLK、MOSI、MISO 和片选信号。主机产生时钟，从机在时钟边沿采样或输出数据。SPI 支持全双工，速率可以达到数 MHz 到数十 MHz。

SPI 优点是速度快、协议简单、适合 Flash、显示屏、ADC 等高速外设；缺点是每个从机通常需要独立片选线，不适合大规模节点组网，且没有标准化的流控和应答机制。

## I2C 总线

I2C 是飞利浦公司提出的两线制同步总线，只需要 SDA 数据线和 SCL 时钟线，通过上拉电阻维持高电平。总线上每个器件有唯一地址，主机按地址选择从机，支持多主机和时钟拉伸。

I2C 标准模式速率为 100 kbit/s，快速模式为 400 kbit/s，高速模式可达 3.4 Mbit/s。I2C 优点是节省引脚、适合传感器、EEPROM 等中低速器件；缺点是速率低于 SPI、总线电容限制节点和距离、排障时容易遇到地址冲突和总线拉死问题。

## SPI 与 I2C 的选择

需要高吞吐、全双工、连续数据流时优先选择 SPI；引脚紧张、总线上器件多、速率要求不高时优先选择 I2C。很多传感器同时提供两种接口，可根据主控资源和布线情况选择。

## RS485 总线

RS485 使用差分信号传输，抗共模干扰能力强，传输距离远，适合工业现场。RS485 是半双工总线，需要方向控制，常用 A、B 两根差分线加地线。总线上可以挂多个节点，但同一时刻只能有一个节点发送。

RS485 需要在总线两端接终端匹配电阻以减少反射。Modbus RTU 是 RS485 上最常见的应用层协议，采用主机查询、从机应答方式，广泛应用于工业仪表和 PLC 通信。

## CAN 总线

CAN 是控制器局域网络总线，最初用于汽车电子，后来扩展到工业控制。CAN 使用差分双线传输，采用非破坏性仲裁：多个节点同时发送时，标识符小的报文优先，仲裁过程不破坏高优先级报文。

CAN 报文有数据帧、远程帧、错误帧和过载帧等类型，数据帧携带标识符、数据长度码和最多 8 字节数据，CAN FD 扩展了数据长度。CAN 具有错误检测、自动重发和故障界定机制，实时性和可靠性好，适合动力系统、底盘控制和分布式工业设备。

## 中断与 DMA

嵌入式通信接收数据有两种常用方式。中断方式在每收到一个字节或数据块时产生中断，CPU 读取数据，响应及时但频繁中断会占用 CPU。DMA 方式由 DMA 控制器直接在总线上搬运数据，不经过 CPU，适合高速、大批量数据传输，CPU 只需在传输完成时处理。

实际设计中常把两者结合：接收用 DMA 搬运到缓冲区，达到设定长度或超时后触发中断，由软件解析完整数据帧。

## 常见网络通信

嵌入式设备联网常使用 TCP/IP 协议栈。MQTT 是轻量级发布-订阅协议，适合物联网设备上报数据和接收控制指令。HTTP 适合请求-响应式交互，WebSocket 适合需要长连接和双向实时通信的场景。低功耗无线网络还有 LoRa、NB-IoT 等，适合速率低、覆盖远、电池供电的设备。
